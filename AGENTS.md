# Repository Guidelines

## Project Structure & Module Organization
- `src/` holds the React app (Vite + Tailwind); `App.jsx` stitches sections; `components/` contains UI sections and motion primitives; `hooks/`, `config/`, `lib/`, and `assets/` carry data, utilities, and static media.
- `public/` serves static files verbatim for `index.html` and favicons.
- `dist/` is generated by `npm run build`; never edit by hand.

## Build, Test, and Development Commands
- `npm install` installs dependencies.
- `npm run dev` starts the Vite dev server (default `http://localhost:5173`) with hot reload.
- `npm run build` outputs a production bundle to `dist/`.
- `npm run preview` serves the built bundle locally for release validation.
- `npm run deploy` builds then publishes `dist/` to GitHub Pages (`homepage` in `package.json` and `base` in `vite.config.js` must match the repo path).

## Coding Style & Naming Conventions
- Favor React function components, hooks, and ES modules; component files are PascalCase (e.g., `Hero.jsx`), hooks start with `use`.
- Prefer 2-space indentation, semicolons, and double quotes as shown in `src/App.jsx`.
- Keep Tailwind utility classes in JSX; place animation/scroll helpers in `components/motion/` or `hooks/`.
- Store media in `src/assets/`; only place unbundled files in `public/`.

## Testing Guidelines
- No automated tests exist yet; when adding, use Vitest + React Testing Library.
- Place specs in `src/__tests__/` or alongside code as `Component.test.jsx`; mock Framer Motion/Lenis where animations limit determinism.
- Cover nav anchor scrolling, hero CTA links, and project/experience cards before merging.

## Commit & Pull Request Guidelines
- Use concise, imperative commit subjects (e.g., `Refine hero reveal timing`); add scope when helpful.
- PRs should include a short summary, screenshots/gifs for UI changes, linked issues/tasks, and note any deployment-impacting changes (`homepage`/`base` updates).
- Run `npm run build` (and tests if added) before review; do not commit `dist/` or `node_modules/`.

## Deployment & Configuration
- Keep `homepage` in `package.json` and `base` in `vite.config.js` aligned with the deployed path; update both when switching hosting paths.
- After `npm run deploy`, verify GitHub Pages and custom domain/CNAME settings if pointing `manasjha.online`.
